❗ Il punto chiave

Se leggi il body (bodyInputStream.read(...), response.body(...), ecc.)

✔ Con il tuo meccanismo "leggo solo 1 MB e poi ricostruisco lo stream"

Tu pensi di non leggere nulla…

Hai due modi sicuri:

✅ Soluzione A — Interrompi l’interceptor prima di toccare il body (best)
Esempio
return (request, next) -> {
    var response = next.exchange(request);

    // Guarda SOLO gli header, NON chiamare getBody()
    var cd = response.headers().getFirst("Content-Disposition");

    if (cd != null && cd.contains("attachment")) {
        // NON leggo il body
        // NON avvolgo lo stream
        // NON provo a loggare nulla del body
        return response;   // torna intatta
    }

    // normal logging path ...
    // qui puoi leggere 1MB, ricostruire, ecc.
};
🔴 Importante:
devi mettere l’if PRIMA di qualsiasi codice che fa response.body(), bodyToMono(), getBody(), readAllBytes(), ecc.

❌ Soluzione che NON funziona
Mettere l’if dopo aver iniziato a loggare:

var body = response.getBody(); // <-- già consumato!
if(attachment) return response; // <-- response corrotta
È esattamente quello che sta accadendo nel tuo caso.

❗ Alternativa più robusta
Usa ClientHttpResponseDecorator e fai override di getBody() solo per tipi non-binary.

In stile WebClient:

    return response;  // nessun wrapping

    @Override
    public InputStream getBody() throws IOException {
        // qui fai il tuo "leggo 1MB e ricostruisco"
    }
};

✔ Soluzione A – Salta COMPLETAMENTE l’interceptor per gli attachment
Non devi solo “saltare il log”, devi saltare tutto l’interceptor, cioè non devi nemmeno ritornare la response intercettata.

Esempio:

@Bean
RestClient restClient(RestClient.Builder builder) {
    return builder
            .requestInterceptor((request, next) -> {
                var response = next.exchange(request);

                var cd = response.getHeaders().getFirst("Content-Disposition");
                if (cd != null && cd.contains("attachment")) {
                    // ⚠ NON devi restituire “response”
                    // perché è già decorato dall’interceptor
                    // devi rifare un next.exchange SENZA interceptor

                    return nextWithoutInterceptors(request);
                }

                // normale log response...
                return response;
            })
            .build();
}

// modo per rieseguire la richiesta senza l’interceptor
private ClientHttpResponse nextWithoutInterceptors(ClientHttpRequest request) {
    var factory = new HttpComponentsClientHttpRequestFactory(); // o quello che usi
    var rawReq = factory.createRequest(request.getURI(), request.getMethod());
    rawReq.getHeaders().putAll(request.getHeaders());
    request.getBody().transferTo(rawReq.getBody());

    return rawReq.execute();
}

bypassa completamente l’interceptor per i download.

🧱 1) Interceptor “safe” per il logging della request
public class RequestOnlyLoggingInterceptor implements ClientHttpRequestInterceptor {

    @Override
    public ClientHttpResponse intercept(HttpRequest request,
                                        byte[] body,
                                        ClientHttpRequestExecution execution)
            throws IOException {

        // LOG REQUEST (headers + body se vuoi)
        logRequest(request, body);

        // ⛔ NON toccare la response
        return execution.execute(request, body);
    }

    private void logRequest(HttpRequest request, byte[] body) {
        System.out.println("=== REQUEST ===");
        System.out.println(request.getMethod() + " " + request.getURI());
        request.getHeaders().forEach((k, v) -> System.out.println(k + ": " + v));

        if (body != null && body.length > 0) {
            String s = new String(body, StandardCharsets.UTF_8);
            System.out.println("Body: " + s);
        }
    }
}
Questo è garantito safe:

non legge la response

non apre flussi

non wrappa

non crea problemi ai download binary
